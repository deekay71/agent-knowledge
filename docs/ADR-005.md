# ADR 005 — Local graph views, revision comparison and export
Date: 2026-10-18 (UTC). Status: accepted; subsequent publication approval is recorded
in the [release handoff](VIEWER-RELEASE-20261018.md).

## Context

P1 provides evidence-aware navigation. Large fixtures expose the cost of synchronous force
layout, and users need repeatable views, local revision comparison and portable captures.
These capabilities must preserve the read-only corpus boundary and distinguish UI grouping
from authored knowledge.

## Decision

Use deterministic structural grouping derived from existing node metadata. Groups and
aggregate edges are presentation objects, visibly distinguished from canonical notes and
explicit relations. Expanding a group must recover its actual members and edge provenance.
Filters determine the eligible visible set; grouping cannot reveal filtered/private notes
or manufacture new knowledge relations.

Use a bounded deterministic layout for large graphs instead of blocking the browser with
the initial force simulation. Allow browser-local saved positions and preferences scoped
to an opaque corpus identity. Treat stored JSON as untrusted, cap its size and validate
finite coordinates/known IDs. Store no note bodies or complete graph snapshots.

Auto-refresh is opt-in, pauses in hidden tabs and avoids overlapping snapshot requests.
Reconcile selection, filters and positions against actual IDs. A failed/private snapshot
must clear stale content, including exports and comparison output. Do not turn refresh into
an ingest, commit or background daemon.

Revision comparison accepts full local commit IDs within the current root's HEAD ancestry.
No user revision expressions, arbitrary refs, network fetch or gitfile traversal are allowed.
Read an allowlisted, bounded object store through confined regular-file reads into a private
temporary bare repository. Do not copy original configuration, hooks, alternates, replacement
refs or user/worktree metadata. Invoke Git only against that isolated copy with configuration,
environment, output and time limits. This avoids writing an independent Git pack parser.

Read only canonical raw/wiki Markdown from both trees, excluding the workflow log. Validate
both snapshots before returning a comparison; invalid/private input fails the entire request.
Report structural added/removed/changed notes and explicit edges. A byte or metadata change
is not a semantic explanation or a conclusion about which source is correct. Repositories
outside the supported confined layout or resource limits return an explicit unsupported/error
result; they do not trigger a broader read or fetch.

Export requires a deliberate confirmation describing possible sensitive content. JSON contains
only the selected eligible graph projection and its provenance; the image captures the current
graph view. Mark UI aggregates separately or map them back to actual member relations. Bound
output/image size and recheck snapshot identity before downloading. Export stays in the user's
browser, without adding a server write route or uploading to another service.

## Consequences

Browser storage is a convenience, not shared knowledge or version history. Local Git object
copies use bounded temporary disk space and are removed after comparison. Linked worktrees,
submodule gitfiles and oversized object stores may not support comparison even when their
working-tree graph remains readable. Publication requires separate user authorization;
approval for this release does not authorize future unrelated changes.

The Git environment controls and plumbing behavior are based on the official
[Git command/environment reference](https://git-scm.com/docs/git),
[cat-file](https://git-scm.com/docs/git-cat-file) documentation. Image export uses the vendored
library's [Cytoscape PNG interface](https://js.cytoscape.org/#cy.png), with explicit bounds.
Tests must cover packed and loose objects, malicious paths/configuration, private old revisions,
actual browser navigation/refresh and downloaded artifacts, separately from semantic review.
