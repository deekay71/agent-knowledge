# ADR 002 — Derived portable Markdown vault
Date: 2026-10-17 (UTC). Status: accepted for local implementation.

## Context

The canonical wiki uses `---json` metadata for dependency-free schema validation and structured
claims. Markdown applications do not consistently render that header as properties, and metadata
paths alone do not guarantee native graph links. Readers need an accessible linked view without
changing the storage contract or creating a second editable source of truth.

## Decision

Add `scripts/export_vault.py` to derive a portable vault from canonical `wiki/` and `raw/`.
Default output is the small committed `vault/` tree; `--output NEW_DIR` supports a separate
snapshot. Preserve relative paths, emit standard YAML front matter with simple properties,
and render nested claims and contradictions as readable Markdown with source links. Preserve
scope, uncertainty and inference labels. Render supersession relationships as Markdown links.

Include `Home.md` navigation and `graph.json` for typed metadata relationships with SHA-256
provenance. Native Obsidian graph links remain untyped; consumers that need relationship types
must inspect `graph.json`. No application plugin, graph service or model call is required.

Keep canonical `---json` files unchanged by export. Author through the existing contribution,
index/log, lint and review workflow, then refresh the derived view. There is no reverse import
or bidirectional sync. An exported raw note is a transformed presentation copy, not a replacement
for the immutable archived source.

`--check` compares the current input fingerprint and generated files without writing.
`--refresh` replaces only unchanged managed output, refusing locally edited generated files
and unknown files outside `.obsidian/`. Preserve and ignore `.obsidian/` preferences. An external
copy uses the same explicit check/refresh model and never silently follows source changes.

## Consequences

Readers can browse a committed snapshot directly from a pinned submodule. Standard relative
Markdown links improve portability, but properties and graph support depend on the reader.
Obsidian's actual GUI is not tested by file-level export tests. Do not promise uniform behavior
across applications or imply that a graph is semantic verification.

The committed derived view duplicates some content and requires refresh when canonical inputs
change. Review source and view diffs together, and use `--check` to detect drift. Personal notes
belong outside the generated tree; otherwise safe refresh intentionally refuses to overwrite
them. Keep app preferences out of shared commits.

A vault includes raw sources and is not an access-control or redaction layer. Export does not
publish, configure sync, or change sharing permissions. Provenance hashes establish byte identity,
not factual correctness or a right to distribute content.

Rejected alternatives: migrating canonical metadata solely for one viewer would alter the
existing contract; a plugin would add an application dependency; bidirectional editing would
require conflict resolution and source-integrity rules beyond this feature.
