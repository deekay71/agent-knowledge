# ADR 003 — Local read-only canonical graph viewer
Date: 2026-10-18 (UTC). Status: accepted for local implementation; publication separate.

## Context

The portable vault serves Markdown readers, including Obsidian, but its generated notes and
native graph do not provide a repo-owned view of typed edges, provenance or source snapshots.
Readers need to inspect the shared wiki without installing a desktop note application. The
viewer must preserve the existing authoring, review, version pinning and immutable-source rules.

## Decision

Add a Python standard-library HTTP server bound exclusively to `127.0.0.1`, with local static
assets and a read-only graph endpoint. `scripts/viewer.py --check` validates a snapshot without
starting HTTP. The server runs only when explicitly launched and never fetches, commits,
changes a submodule pin, exports files, writes chat logs or invokes an LLM.

Read canonical regular Markdown files in `raw/` and `wiki/`, including the canonical index.
Exclude `wiki/log.md` and the generated vault/Home so workflow events and copied content do
not become graph nodes. Do not open project context, inbox files, arbitrary attachments or
external review records. Perform bounded, directory-descriptor-based reads that reject
symlinks; compare two scans to detect concurrent edits. Reject malformed/private input instead
of returning a partial graph that could be mistaken for the complete knowledge set.

Return nodes with scope, status, versions, source metadata and bodies. Derive only explicit
edges: supported inline Markdown links, sources, claim sources, contradiction sources and
supersession fields. Keep relation kind and originating metadata field/body on each edge;
multiple edges between the same pair can have different provenance. Do not infer similarity,
merge evidence into facts, or treat a graph edge as validation of the related claim.

Build each API response afresh in memory; no persistent graph cache or watcher is introduced.
Manual Refresh reloads the snapshot. Report source fingerprint, best-effort Git HEAD, index
filesystem mtime and load time separately. Read HEAD/loose/packed refs only through an in-root
`.git/` directory; never run a Git subprocess or follow a gitfile to external metadata. Linked
worktrees and submodules using a gitfile therefore report a null revision while retaining
canonical viewing. A HEAD label does not certify that the current working files were committed
or that their contents have been semantically reviewed.

Use pinned prebuilt Cytoscape.js, markdown-it and DOMPurify distributions from the official
npm registry. Check in license texts and a manifest with original URLs/integrity/file hashes.
Runtime needs neither npm nor a CDN. The application's code, layout and branding are specific
to this repository; no Graphify code, assets or branding are reused.

Serve only fixed static routes and the graph endpoint, require matching loopback Host/Origin,
and reject write methods. Render note data as untrusted content with HTML disabled, sanitized
Markdown output and a restrictive CSP. Do not load external images, fonts or embedded scripts.
These controls are local defenses, not authentication between local processes or permission
to publish the source corpus. Actual content rights still require review.

## Scope and consequences

P0 provides graph navigation, title/ID search, type/topic filters, a reader with backlinks and
outgoing references, edge provenance and manual Refresh. Keep full-text search, hops, path
finding, context copying and diagnostics for P1. Clustering, Git diff, auto-refresh and viewer
export remain P2. The existing portable exporter remains available independently.

Canonical Markdown remains the only authored source. The viewer adds no editor or reverse
sync and does not replace full `wiki.py lint --base`, staged hooks or semantic review. Its
validation deliberately does not read log history or external verification records. The API
sends the complete eligible snapshot to the local browser, subject to bounded file/node/byte
limits; those limits are resource guards, not a claim that the UI is fast at every bound.

Starter node counts differ intentionally from the portable vault: the canonical viewer has
four nodes; the six-note portable view includes generated Home and the workflow log. Use a
separate synthetic fixture generator for larger screenshots and measurements, never inflate
the shared wiki with invented production guidance. Report backend checks, browser behavior,
security regressions and performance measurements separately as they are actually run.

The confined-read implementation requires POSIX-style file descriptor support. Windows and
other platforms need explicit validation before support is claimed. There is no daemon,
network-facing deployment, remote publication, automatic agent activation or sharing change.

## Alternatives

Reading the portable vault would add stale-export checks and mix generated navigation/log
with canonical concepts. Building a second editable store would require synchronization and
conflict rules. A server/database framework or frontend build chain would add runtime setup
that the bounded local use case does not need. All are deferred without changing the storage
contract.
